01 — Scope of work

Desktops Imaging, configuration, deployment, and repair. Windows 10 and 11. macOS Sequoia on Intel and Apple Silicon. Ubuntu LTS servers and workstations. Printers. Cisco and Nortel VoIP phones.
Identity Active Directory and Group Policy. Macs joined to Active Directory and LDAP. Microsoft 365 and Google Workspace.
Moves Exchange since 5.5, upgraded in place and side by side, including the move to Microsoft 365. Active Directory swing migrations, and Active Directory into Microsoft 365. Production Linux on Google Cloud. Virtual machines and S3 on AWS. A lighter share of the same work on Azure.
Hosts Virtual machines on VMware vSphere, XenServer and XCP-ng, and Microsoft Hyper-V. The same servers that used to sit in the rack, run as guests, including the Linux hosts on Google Cloud and the virtual machines on AWS.
Remote On site and remote. SSH. RDP across a WAN through Microsoft RD Gateway.
Network Cisco, pfSense, SonicWall, PIX, and ASA. Barracuda for spam and backup.
Close The record says what failed, what was tried, and the result. A ticket is not closed until the user is working. When the problem is outside the experience, it is handed on.

02 — Software

The software work sits next to the administration. Compiling, scripts in the shell and in Python, and small programs for the machines already in the shop.

Build Linux server and workstation administration includes compiling software from source when a package is missing, old, or wrong for the machine.
Scripts Shell scripts for the machines under administration. The script says what it does, and it can be run again. The same standard as the ticket notes.
Python Python, as another way to write those scripts and small programs. Logs, inventories, and the short tools that sit beside the shell, when Python is the clearer of the two.
C C, Unix C, and C++. Small programs beside the system work. On Windows, that work has been done in Visual Studio.
Web HTML, JavaScript, and Node.js for pages and small tools. Some of this is stronger than the rest. IIS when a Windows server is the host.

03 — Agents

The small programs are written by hand and with the coding agents. The agent does not close the ticket. The diff is read, the script is run again, and the note says what changed.

Editor Cursor. The files stay in the editor. What is kept is the diff, not the chat.
Terminal Claude Code and Grokcode, for an edit that is longer than one completion.
Standing Grokbot and Claudebot, when the job is an agent left running rather than one session at the keyboard.

04 — For the record

Ian Saint-Evens is a lifelong resident of Chico. He has spent more than 30 years imaging, configuring, deploying, and repairing desktops and the peripherals on them. That work is what Saint-Evens Consulting does now: first- and second-line support, remote and on site.

The desktops run Windows 10 and 11, macOS, and Linux, with Microsoft 365 and Google Workspace. Behind them is Windows Server, Group Policy, Active Directory, and Exchange. The moves are Exchange into Microsoft 365, Active Directory swing migrations, and servers onto Google Cloud and AWS, with a lighter amount of Azure. On the premises the hosts are VMware vSphere, XenServer and XCP-ng, and Hyper-V. Linux work includes server and workstation administration, compiling software, and scripting in the shell and in Python, plus some C. Macs are joined to Windows Active Directory and LDAP.

Previously held, not current: CCNA. MCSE for Windows NT 4.0. IT coursework at Mesa College, San Diego. Some college, not a graduate.
